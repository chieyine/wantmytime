## Local run

- `docker compose up --build db api` starts local PostgreSQL, runs the dedicated migration job, and starts the API when Docker is available. For a host-run API, apply migrations first with `cd services/core && go run ./cmd/api migrate`; `make api` does this before starting the API. `cd apps/web && npm ci && npm run dev` starts the web app.
- `docker compose up --build` builds the Node web image, API image and Nginx same-origin gateway; browse the gateway at `http://127.0.0.1:5173` when Docker is available.
- The local payment simulator requires both `APP_ENV=local` and `LOCAL_PAYMENT_SIMULATOR=true`; it creates clearly synthetic bookings and no money movement.
- Compose routes API email to local Mailpit by default; open `http://127.0.0.1:8025` to inspect messages. When running the API directly on the host, set `SMTP_HOST=127.0.0.1`. Production requires a verified sender and provider credentials. Local OTP logging is disabled in Compose; never enable OTP logging or simulator flags in production.
- Bootstrap a verified operations owner only after setting a base64-encoded 32-byte `OPS_MFA_ENCRYPTION_KEY` and securely injecting the base32 authenticator secret as `OPS_BOOTSTRAP_TOTP_SECRET`: `aside-api bootstrap-admin verified-owner@example.com`. This grants read, account-restriction and session-revocation permissions. Do not put secrets in command arguments, logs or shell history.
